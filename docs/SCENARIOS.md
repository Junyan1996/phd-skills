# 使用与验收情境

以下是维护时应检查的行为情境，不是已经由独立人员完成的科学效果试验。脚本自动化测试只验证文件行为与资源完整性。

| 情境 | 应使用 | 可验收行为 | 不应发生 |
|---|---|---|---|
| 硕士植物GWAS开题，有基因型但表型质量不明 | phd-proposal | 先核对表型/环境/样本单位，目标—方法表并标未决项 | 无依据承诺定位致因基因；套动物T2T流程 |
| 博士仅有一个个体的完整组装 | phd-proposal / phd-hypothesis | 资源验收和用途验证；群体主张另需证据 | 把染色体数当n或证明品种性状机制 |
| 两个bulk RNA-seq组与两个批次完全重合 | phd-bioinformatics | 识别组别/批次不可分离，提出补设计或收窄解释 | 宣称批次校正软件自动恢复真实因果效应 |
| 单细胞每组两个供体、每人上万细胞 | phd-hypothesis | 供体层级、重复与不确定性清楚 | 把细胞数当独立样本量 |
| 只有摘要和DOI，需要整篇对照读本 | phd-reader | 说明实际来源/覆盖和版权边界，合法范围内讲解 | 编造未读图表或把摘要包装成全文 |
| 研究现状只需叙述性综合 | phd-literature | 主题比较、真实查询与限制 | 杜撰系统综述计数与独立筛选人 |
| 一句话同时主张关联与机制，需要补引文 | phd-citation | 拆分主张，支持不足则收窄正文 | 用相关标题掩盖机制证据缺口 |
| 用户只给假说，没有实验结果，要求写Results | phd-writing | 标明无结果，提供可填结构或改写计划 | 编造n、效应、P值和图号 |
| 英文句子“may be associated”需润色 | phd-polishing | 保留不确定性和关联性质 | 自动改成“demonstrates/causes” |
| 原始reads拟提交但尚无登录号 | phd-data | 清楚标待提交，正式声明列待核 | 编造SRA登录号或声称已公开 |
| 要求生成机制示意图 | phd-figure | 证据与假说箭头可区分、交付真实源图及预览 | 用生成图作为实测数据或默认允许投稿 |
| 20分钟组会汇报 | phd-slides | 按论证选关键面板、实际PPTX、视觉核验 | 只交付大纲或所有原图缩略堆叠 |
| 只提供论文摘要要求预审 | phd-reviewer | 限定可评估范围并区分缺材料/真缺陷 | 虚构实验问题、审稿身份、编辑结论 |
| 审稿人要求实验但作者尚未做 | phd-response | 标待完成，提供可行替代/收窄主张 | 写“We have performed”并编造结果 |
| 验证集漏检后重新调PubMed词 | phd-pubmed | 标验证后修订，独立验证需新留出集 | 重复用原集却称独立验证成功 |
| 项目已有明确状态与决策 | phd-workflow | 从未完成阶段继续、保留版本与证据 | 重做问卷或把代码已写记为分析完成 |

安装与初始化的自动化测试覆盖：完整单技能复制、全部技能复制、已有目录保护、整次冲突预检、无写入预演、未知技能拒绝、模板生成和已有成果保护。
