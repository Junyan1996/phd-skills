# 审稿回复与返修

读取编辑信、全部意见、稿件版本和已完成修订。确定用户要分诊、起草、审核还是修改回复；先沿用已知期限与投稿状态，不把所有意见机械视为新增实验指令。

建立问题账本：`comment_id, reviewer_or_editor, original_comment, issue, requested_action, decision, evidence_status, manuscript_change, locator, response_status, owner_or_next_step`。复合意见拆分编号但保留原顺序与原意，不能漏掉难答部分。

按性质处理：澄清、补方法/引用、再分析、实验、限制、主张收窄、不同意或相互冲突。优先识别影响核心结论的意见和编辑必须满足的条件。

逐条回复结构：直接回答→实际采取的行动/理由→证据或修订内容→定位。只有真正完成并核验才写“We have…”；计划、未完成和待作者确认用明确标记，不能编造图、n、统计量、行号或新增实验。

无法完成的实验说明科学理由、可行替代和剩余边界；不要用工期作为唯一理由，也不要承诺并未获资源支持的工作。不同意时基于证据回应并改善稿件澄清；审稿人冲突时说明取舍及与编辑要求的关系，不假称获得批准。

定位使用实际修订稿的节/图/表/页/行；排版后行号可能变化，最终重新核验。回复中每个“已修改”应能在稿件找到，稿件中的结论调整也要在相关回复一致体现。

交付完整逐点回复、修订映射和未完成项；仅用户要求时另写致编辑总信。语气克制具体，不堆感谢或假装接受所有意见。此流程不自动向期刊发送或提交。
