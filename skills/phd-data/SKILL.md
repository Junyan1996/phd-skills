# 数据与代码可用性

先盘点支持论文主张所需的原始数据、处理数据、图表source data、代码、模型、参考资源与复用数据，确认实际状态、所有权和用户要求。

建立清单：`resource_id, type, supports_claim_or_figure, owner, location, identifier, version, access_route, license, restriction_basis, metadata, release_status, unresolved`。

为每项选择真实访问路径：公开仓库、受控访问、第三方限制、论文/补充材料内、复用公开资源、确有理由的申请获取或不适用。保护隐私/知情同意要求与项目确有的限制；不能把FAIR等同全部公开，也不能空泛“合理请求”代替可用路径。

推荐仓库前查当前官方范围、数据类型要求和政策；基因组原始reads、组装/注释、表达矩阵及代码可需要不同位置，并用项目ID/元数据相连。论文DOI、数据DOI、BioProject与具体数据登录号不是可互换标识。

正式声明逐项映射数据→位置→标识→版本→访问条件；拟提交与已公开必须区分。未知登录号/许可/日期/委员会标为待补，不编造。复用数据列原始来源及版本；代码补环境、依赖、参数与运行说明。

核验元数据的标题、作者、关联论文、物种/样本说明、变量字典、单位、文件格式、参考版本与持久标识。检查链接实际可访问、登录号状态、访问申请联系人/流程和限制理由。

交付可粘贴声明及未决项、数据/代码共享清单；中文请求可附术语核对，正文语言按用户要求。规划不等于提交：外部上传、开放访问、许可选择和不可逆发布按当前任务具体授权执行，不自动使用私有资料作公开演示。
