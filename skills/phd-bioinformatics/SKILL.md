# 生物信息学研究流程

从科学问题、输入和目标结果出发，先识别用户要方案、代码、审核还是实际运行。沿用已有工作流引擎和环境；不凭技能调用自动启动昂贵分析或集群作业。

## 输入与设计契约

记录数据所有者/来源、登录号与版本、样本表、独立个体/家系/地点、组别与协变量、测序类型、参考基因组/注释/坐标系、输入格式、算力、输出和运行范围。敏感样本ID留在本地，公开搜索只用必要的非敏感描述。

在跑软件前检查：组别与批次能否分离；配对/重复测量是否建模；亲缘/群体结构；表型和样本是否对应；发现与验证数据是否独立；分析单位与主张是否匹配。设计不可识别时给缩小主张或补数据方案，不能靠参数调节宣称解决。

按任务阅读[分析分流](references/routes.md)。推荐工具、参数或命令前核对当前官方文档与实际版本；不写“最新”而不查。网络受限时标明版本适配待核。

## 实现或排错

1. 保留原始数据；配置、样本表、日志和结果分离，显式列出输入/输出与依赖。命令不含凭据；记录环境、参考版本、随机种子、重要参数和完整日志。
2. 先验证样本/文件完整性与格式，用小规模合法样例或子集检查接口、单位、坐标和预期输出；子集结果不冒充完整分析。
3. 质控要连接可能的偏差与处理决定，阈值须依据任务、数据分布或方法证据；不要把通用阈值当铁律。保存排除原因，避免按想要的结果过滤。
4. 排错先取最小复现、版本、报错和中间产物，区别输入、设计、软件、资源与生物学差异；每次改变要有可检验原因，不盲目重复全量运行。
5. 统计比较包含适当基线、效应与不确定性、多重检验和敏感性；验证区分技术复核、同数据再分析与真正独立证据。
6. 报告实际运行范围、完成/失败步骤、被排除样本、资源消耗和未决项。只有检查输出及日志后才写“运行成功”；不能把计划写成Methods已实施。

交付可复现源代码/配置、运行说明、输入输出清单、质控与结果摘要；用户仅要求方案时交付对应计划即可。结论必须对应实际数据，不从候选基因名单直接升级为机制。
